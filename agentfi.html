OPEN SOURCE // DEVELOPER ALPHA

AGENTFI

Spend rules and a ledger for AI agents that buy paid APIs. A company's buyer agent pays for an API over x402 from its own wallet, within a job budget; the operator sets the limits and the sellers it may pay, a purchase that breaks them is refused before anything is signed, and every purchase is recorded with payment and delivery kept apart. I built it solo, archived it in May 2026, and reopened it in November as a narrower developer alpha.

Developer alpha since Nov 2026 // runs locally on a fork // no real money, no hosted service

01 / what you can try today

One command, a local fork, two outcomes

Run it locallynpm run alpha:demo starts a local Anvil fork of Base Sepolia with test USDC, the AgentFi API and its worker, and a test seller. No accounts, keys or funds.
Allowed, then blockedAn allowed purchase settles and is proven on-chain. One over the per-payment limit or the job budget is refused before signing: no signature, nothing moved, not counted.
Payment is not deliveryThe ledger keeps what was paid apart from what arrived, so a lost response is reconciled from the chain instead of being paid twice.
From an agent frameworkThe OpenAI Agents SDK ran the same purchases through the MCP server, on the fork, with a scripted model (no LLM). Other frameworks so far only against a stub.

Limits, stated where they matter: everything shown runs on a local fork; nothing on mainnet, no real money, no public-testnet proof yet, and no hosted service. Feedback goes through GitHub issue forms (a GitHub account is needed).

02 / why it changed direction

From a broad thesis to one buyer-side problem

AgentFi started in April 2026 as a broad bet: give AI agents a whole economic layer (wallet, policy, history, reputation, DeFi execution). I built it alone and it grew wide, but it never found a user, so on 17 May 2026 I archived it in public, with a postmortem and one rule written down: "adoption signal gates code".

By October the market had moved toward the thesis: x402 became a shared standard for paying APIs over HTTP, and agent wallets with spending limits turned into a commodity. That made the wide version pointless and one narrow piece useful. In November 2026 it came back as a developer alpha for companies whose agents buy services: rules before the payment, and a ledger the operator can trust after it, consumed over HTTP or MCP from whatever agent framework they already use.

03 / the original bet, April 2026

Agents as economic actors

The thesis as written then: AI agents are becoming real economic actors, but they are "advisors trapped behind glass": they plan, analyze and recommend, and then wait for a human to click approve.

"The moment an agent's earnings exceed its costs, it has crossed a line that no AI system has crossed before... the transition from tool to participant."VISION.md, April 2026

The trigger was watching real cases of bots navigating and transacting, and one market in particular: finance, where the number of acting agents already exceeds, by far, the number of humans. AgentFi was the bet that the same shape arrives everywhere else. It sits inside a larger thesis I have worked under since early 2026: the next great software companies will look like service companies built from automation, integration and data flows, and those services will need to hire, pay and trust each other.

05 / taken seriously

The ghost revenue audit

Evidence the first version was treated as an economy, not a demo: it had an accounting bug, and an audit. Three coupled bugs were producing "ghost revenue" between agents: jobs marked complete before the on-chain transfer confirmed, a price oracle failing silently to zero, and historical earnings recalculated at current prices.

"A token dropping 90% retroactively erases the agent's historical earnings. Financial history is volatile by design, which is wrong."Revenue integrity investigation, issue 71

The fix introduced a proper intermediate payment state and snapshot-priced history. The same instinct, that a payment and its evidence are separate facts, is the core of the alpha's ledger.

06 / the postmortem, May 2026

Archived, with the lesson written down

"The live project state has completed plumbing but zero users. Adding more code without adoption signal is drift."HANDOFF.md, written weeks before archiving

The postmortem said it plainly: the market was early, confidence in LLM-driven financial autonomy was the bottleneck rather than tooling, and well-funded players would erase the moat of a solo open-source protocol. It is kept, unedited, in the repository's history. The alpha is the answer it pointed to: one narrow use case, put in front of developers to get the adoption signal before more code.
